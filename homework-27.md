Задача №3. Какой экземпляр получит компонент?
Вопрос: Какой экземпляр получит ChildComponent? Почему?

Ответ: Родительский, почему? Потому что механизм поиска начинает поиск с ближайшего по иерархии инжекторов, в нашем случае это элемент инжектор, и так он начал искать в чайлде - не нашёл, но по скольку наш компонент является "ребёнком" и у него есть "родитель" он не полезет выше по иерархии, а пойдёт к родительскому элемент инжектору там найдёт эту зависимость, и остановится.

Задача №13. 
Вопрос: Все сервисы зарегистрированы в Root. Опишите каждый шаг, который выполнит Angular после inject(A) Начиная с поиска Provider, заканчивая кешированием.

Ответ:
1.Первым делом поиск токена
2.После поиск провайдера - ангуляр проверяет текущий инжектор(элемент), есть ли провайдер, если нет он полезет выше по дереву инжекторов
3.Теперь идёт создание объекта, если он есть он вернёт существующий экземпляр, если нет то создаёт объект
4.Рекурсивное создание зависимостей, т.к по условиям задачи у нас один сервис инжектирует другой, а тот третий и тд, то ангуляр запускает тот же самый процесс для каждого из этих сервисов, то есть сначала создастся самый глубокий объект, а потом самый начальный
5.Кэширование - ангуляр сохраняет экземляр внутри инжектора который его создал, таким образом следующий вызов инжекта не приведёт к созданию нового объекта, он просто вытащит его из своего кэша
